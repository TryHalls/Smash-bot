# Task 010 Gate C2c

Gate C2c is a TRAIN-only candidate-manifest and dependency/storage preflight.
It does not train a model, inspect HOLDOUT, or modify the production detector or
tracker.

## Candidate TRAIN manifest

The manifest is generated by the same `yellow_candidates` implementation used
by Gate B, with spatial identity ordering (`y`, `x`, `area`) applied only after
proposal generation.  Proposal generation does not consume ground-truth
coordinates.  Patches are regenerated in memory using the frozen contract:

- BGR source, 96x96 crop centered on `floor(candidate + 0.5)`;
- `BORDER_REFLECT_101` padding;
- RGB conversion;
- `INTER_AREA` resize to 64x64;
- contiguous `uint8` bytes for the SHA-256 only.

`data/task010/candidate_manifest_train.json`

Visible labels use one nearest positive at `<=10 px`, ignore at `10–30 px`,

contribute 990 trainable negatives.  Ambiguous or unresolved labels would be
ignored and non-trainable; none are present in the frozen snapshot.  The five
Task 009 DEV negative-check frames are not in this manifest and are never fit.

The combined future LOBO policy is frozen as:

- validate `A_01`: DEV training `B_01` + `C_01`, TRAIN groups B + C;
- validate `B_01`: DEV training `A_01` + `C_01`, TRAIN groups A + C;
- validate `C_01`: DEV training `A_01` + `B_01`, TRAIN groups A + B.

HOLDOUT is sealed and was not decoded or used for fitting.  The generator was
run twice from the same inputs; both manifests were byte-identical with the
SHA above.  No image, video, absolute path, or local cache is tracked.

## Dependency and storage preflight

Observed on 2026-10-01:

- Linux x86-64, Python 3.11.2;
- existing runtime: NumPy 2.4.6 and `opencv-python-headless` 4.14.0.94;
- `torch`, `torchvision`, `onnx`, and `onnxruntime` are not installed;
- free space after the manifest gate: 1,509,715,968 bytes.

No package or model was installed or downloaded.  The current official CPU
index exposes a CPython 3.11 x86-64 `torch==2.14.1+cpu` wheel with a payload of
196,227,172 bytes.  ONNX is not required at runtime; if export validation is
authorized later, the current CPython 3.11 `onnx==1.23.1` wheel is the
candidate (8,886,608 bytes), with its small protobuf/ml-dtypes dependencies.
TorchVision is intentionally excluded because the frozen model is custom and
does not require it.  ONNX Runtime is also excluded because production runtime
is OpenCV DNN.

The compressed payload alone is not a safe installed-size projection: PyTorch
also expands native libraries and requires temporary wheel space.  With only
about 0.33 GiB above the 1.10 GiB hard floor, installation was deliberately
deferred.  This is a preflight result, not an installation approval.

## Frozen CNN protocol (not trained in C2c)

The single initial scratch protocol is:

- target: candidate-node scorer;
- input: canonical 64x64 RGB patch, converted to float32 NCHW with
  `(pixel / 255.0 - 0.5) / 0.5`;
- architecture: `Conv(3→8, 3x3, pad=1) → ReLU → MaxPool(2)`;
  `Conv(8→16, 3x3, pad=1) → ReLU → MaxPool(2)`;
  `Conv(16→24, 3x3, pad=1) → ReLU → MaxPool(2)`;
  `Flatten → Linear(1536→32) → ReLU → Linear(32→1)`;
- 54,089 trainable parameters, no BatchNorm, Dropout, pretrained weights, or
  TorchVision dependency;
- scratch fit with deterministic seed `20261001`, CPU, `num_workers=0`,
  `Adam(lr=1e-3, weight_decay=1e-4)`, batch size 32, 40 epochs, and binary
  logits with `pos_weight = trainable_negatives / trainable_positives`;
- ignored candidates are excluded; no negative subsampling;
- export target: ONNX opset 17, then OpenCV DNN CPU for production inference;
  export parity must be checked before any integration;
- learned acquisition is evaluated only in the frozen combined LOBO protocol;
  HOLDOUT remains a single later evaluation.

The inherited performance gate remains scorer p95 `<=8 ms/frame` for the C1
benchmark, with acquisition/reacquisition allowed to batch proposals while
confirmed tracking continues to use the geometric gate.  No training or
production integration is part of Gate C2c.
